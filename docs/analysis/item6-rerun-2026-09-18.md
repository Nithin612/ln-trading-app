# Queue item 6 — D5 / D1 re-run under the delete treatment (2026-09-18)

**What changed vs the published runs: TWO things, and only two.** (1) item 4's delete treatment removes trades whose fill was already through its own stop — trades the live engine refuses and every study silently counted as +1.000R (M64). (2) inference is cluster-robust by entry session instead of iid.

## ⛔⛔ READ THIS FIRST — THE PUBLISHED D5 AND D1 ARE NOT REPRODUCIBLE

I intended to hold the cohort fixed and change only two things. **I could not, and neither
can anyone else.** `_load_frames` does not have a cohort; it has a QUERY whose answer moves:

```sql
WHERE s.is_active AND o.time >= '2023-07-03' ... ORDER BY mdv DESC LIMIT 250
```

`stocks.is_active` was **1,322** when D5 and D1 published on 2026-09-08. **D2′b repaired the
universe on 2026-09-14 and it is now 2,292** (+970). The liquid pool the top-250 is drawn
from is **950 names today**. So the same call returns a materially different population, and
the corpus went **1,152 → 3,267 signals** with nothing in the study changed.

⇒ **Do not compare any number below against its published counterpart.** The before/after
columns within this run are valid — they differ in exactly one thing — but the published
`|t| ≤ 0.65` and `−0.026R` were measured on a set that no longer exists and cannot be
rebuilt, because the flag that defined it was overwritten in place.

⭐ **The generalisable rule, and it is the estimand trap again in a new place: a cohort
defined by a live query against MUTABLE STATE is not a cohort, it is a timestamp.** Same
family as `313 + 617 + 797` (the holdout seal, same night), as `kite_instruments` being
upserted in place so yesterday's state was already gone, and as `load_frames` ranking on
`now() - 180 days`. **A study that wants to be reproducible must PIN its name set — store
the list — not re-derive it.** `liquid_as_of` (item 14) is the primitive for doing this
properly; nothing in D5 or D1 uses it yet.

⚠ And the cohort remains look-ahead-selected regardless: liquidity is ranked across the
WHOLE window, and `is_active` is today's flag. That was NOT repaired here — item 6 asks
whether the delete treatment and an honest SE change the verdicts, and changing the cohort
in the same pass would make the answer unreadable.

⇒ **estimator: cluster-robust by entry session.** The dependence is a GROUPING (4.6 trades per session sharing that session's market move), not a lag, so a serial-correlation correction would be the wrong instrument.

**Delete treatment: 0 of 3267 baseline signals (0.000%).**

⭐ **A clean zero deserves more suspicion than a small number, so it was verified rather
than reported.** On a 12-stock sub-sample (214 trades): the predicate FIRES on a constructed
through-stop record (BUY filled 50 against a stop of 60 → refused), and in the real corpus
**no fill lands at or through its stop** — minimum margin **+0.1202%**, p1 +0.163%, p10
+1.481%, **median exactly +5.000%** (the flat-5% stop rule). Only 7 of 214 sit inside 0.5%.

⇒ **On this population the delete treatment is a genuine no-op**, which is the limiting case
of M85's prediction (+0.0052R at a 5% median stop). The defect item 4 found is real and the
metric is still blind to it; it simply does not occur among daily swing/positional signals
on liquid names, whose stops are wide. It would bite a tight-stop corpus — exactly the
cohort the notional cap already refuses.
